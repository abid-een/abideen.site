# Billkar ERP: Product Engineering Manual

This manual defines the architecture, quality standards, and AI-native development practices for the Billkar ERP project.

## 1. Core Architecture

### 1.1 Backend (`balnce/`)
*   **Module-Based Pattern:** Features are grouped by domain in `src/modules/<domain>`.
*   **Security Pipeline:** Every request must pass through `authenticate` -> `tenantContextMiddleware` before reaching the business routes.
*   **Tenant Isolation:** Multi-tenancy is enforced at the database layer via Sequelize `defaultScope` using `AsyncLocalStorage`.
*   **Services:** All core logic must reside in Service classes (e.g., `AuthenticationService.js`) and must use real database lookups.

### 1.2 Frontend (`balnce-frontend/`)
*   **Domain-Driven Modules:** `src/modules/<domain>` contains localized stores, services, and components.
*   **API Management:** RTK Query is the single source for data fetching. All hooks must be exported from `baseApi.ts` or module-specific API files.
*   **Authentication:** Silent refresh is implemented using a mutex-guarded interceptor to prevent "family reuse" detection failures.

## 2. AI-Native Development Practices

To ensure high-quality, hallucination-free development when working with AI agents:

### 2.1 Atomic Task Logic
*   Break features into **5-minute implementable steps**.
*   Verify every step with a terminal command (Lint, Test, or Build).

### 2.2 The 3-Strike Audit Rule
*   If an AI fails to resolve a bug in **3 attempts**, stop.
*   Re-examine the original error message and read the relevant files from the beginning.
*   Question the architecture before attempting a 4th fix.

### 2.3 Verification Before Assertion
*   Never claim a task is "done" without running the project-specific quality gates:
    *   **Backend:** `npm test`
    *   **Frontend:** `npm run quality:gates`

### 2.4 Context Hygiene
*   Always provide **absolute paths** to files.
*   Keep files focused; if a file exceeds 500 lines, consider refactoring into smaller sub-modules.

## 3. UI/UX 2026 Modernization Standards

### 3.1 Visual Language
*   **Glassmorphism:** Use `backdrop-blur-glass` and low-opacity backgrounds (`bg-white/5`) for cards and overlays.
*   **Neon Accents:** Use the neon palette (`neon-cyan`, `neon-purple`) for high-impact visual cues.
*   **Bento Grids:** Use responsive grid layouts with `shadow-bento` for data visualization.

### 3.2 Typography
*   **Primary:** Inter (variable font).
*   **Mono:** JetBrains Mono for system status and codes.
